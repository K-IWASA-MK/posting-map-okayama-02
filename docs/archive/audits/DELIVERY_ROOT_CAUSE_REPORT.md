# Phase 6: Root Cause Verification

## 監査日時
2026-07-24 15:10 JST

## 事象の分類

### ✅ Confirmed (事実として確認済)
* **二重インデックス問題**: リポジトリ内に2つの `index.html` が存在する。
  1. `/index.html` (Git Root)
  2. `/projects/posting-map/index.html` (Subdirectory)
* **Pages公開ルート設定**: GitHub Pages はリポジトリのルート (`/`) を公開ディレクトリとしている。
* **最新コミットの更新漏れ**: `ab300e1` などの直近のコミット群は `projects/posting-map/index.html` しか更新しておらず、ルートの `/index.html` は放置されている。
* **キャッシュの無実**: `curl` を用いたCDN経由の検証により、キャッシュ起因の巻き戻りではないことが判明（キャッシュMISSでも古いファイルが返るため）。

### ❌ Ruled Out (否定された仮説)
* **GitHub Pagesのビルドエラー**: 直近のコミットもすべて `success` でデプロイ完了している。
* **クライアント側 (PWA/Browser) のキャッシュ**: CDNエッジサーバーへの直接アクセス時点で古いソースコードが返却されている。

## 根本原因 (Root Cause)
「フロントエンドの最新コードが反映されない」という問題の根本原因は、**開発チーム・AIが更新しているファイル (`projects/posting-map/index.html`) と、GitHub Pages が配信しているファイル (ルートの `/index.html`) のパスがズレていること** であると、Phase 2での直接的なソースコード比較（`liff-hud` や `!Array.isArray` 等の実装有無）によって **100% 確定** しました。

デプロイ機構は正常に動作しており、リポジトリのルートディレクトリにあるファイルを正しく配信しています。しかし、そのルートにあるファイル自体が直近の開発で放置されて古くなっているため、ユーザーに届く画面に新機能（`liff-hud`, PC Fallback 等）が全く反映されない状態となっています。

※ 本監査は Read Only のルールの下で行われており、この不整合に対する自動修正は実施していません。設定またはファイル配置の是正が必要です。
